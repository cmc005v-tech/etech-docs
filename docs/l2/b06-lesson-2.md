## 一、五岗位标准架构

| 岗位 | 核心职责 | 三项核心 KPI |
|------|----------|-------------|
| 供应链负责人 | 统筹全链路、战略决策 | 净利率、库存周转天数、断货率 |
| 采购上游岗 | 供应商管理、采购下单 | 来料合格率、采购成本降幅、交期准时率 |
| 库存计划岗（核心中枢） | 需求预测、补货计划 | 预测准确率、断货率、呆滞占比 |
| 物流履约岗 | 头程安排、FBA/海外仓管理 | 物流成本占比、入仓及时率、异常处理时效 |
| 运营协同岗 | 销售预测同步、广告协调 | 预测-库存偏差率、促销备货达成率 |

---

## 二、核心逻辑：五环责任链

```
预测 → 库存 → 补货 → 履约 → 复盘
（运营协同）（库存计划）（采购上游）（物流履约）（全员）
```

**每个环节有明确责任人，是这套架构的核心价值：**

| 环节 | 责任人 | 交接物 |
|------|--------|--------|
| 预测 | 运营协同岗 | 销售预测表（含活动计划） |
| 库存 | 库存计划岗 | 补货建议表 |
| 补货 | 采购上游岗 | 采购订单+交期确认 |
| 履约 | 物流履约岗 | 入仓确认+库存报告 |
| 复盘 | 供应链负责人 | 月度复盘会结论 |

**链条的意义：** 断货时不再互相推诿——预测不准是运营协同的问题，补货延误是采购的问题，入仓延误是物流的问题。责任清晰是效率的前提。

---

## 三、为什么库存计划岗是核心中枢

库存计划岗连接上下游：
- 上游接收运营的销售预测
- 下游驱动采购的补货动作
- 输出结果直接影响断货率和呆滞占比两个生死指标

**中枢岗的画像：** 数据能力强（Excel/ERP 熟练）、业务理解全（懂运营也懂物流）、原则性强（敢于对过量备货说不）。这个岗位招对了，团队效率上一个台阶；招错了，预测和采购两头受气。

---

## 四、架构与业务规模的匹配

| 月销规模 | 建议架构 |
|----------|----------|
| <$30K | 创始人一肩挑+1 名助理 |
| $30K-100K | 3-5 人兼任模式（下节课） |
| $100K-500K | 五岗位逐步专人化 |
| >$500K | 五岗位+各岗 1-2 名下属 |

**扩张原则：** 先加中枢（库存计划），再加两端（采购/物流），最后加统筹——专人化的顺序跟着瓶颈走，不是跟着编制表走。

::: warning 核心要点
五岗位架构的本质不是五个人，而是五条责任链：预测、库存、补货、履约、复盘各有归属。团队小的时候可以兼任，但责任链不能断——兼任是人的合并，不是职责的消失。
:::

## Q&A 预案

**Q1: 我们是纯运营团队，供应链全外包，还需要这套架构吗？**  
A: 需要，但可以轻量化：外包的是执行，不是责任。五环链条里你至少要亲自握住两环：预测（运营协同）和复盘（负责人）——补货和履约可以交给货代/海外仓，但「补多少、什么时候补」的决策权必须在自己手里。外包团队的常见死法就是把决策也外包了：货代说补多少就补多少，断货了才发现预测是错的。架构可以裁剪，决策权不能裁剪。

**Q2: 库存计划岗在中腰部卖家很难招，怎么办？**  
A: 三条路径：一是内部培养——从运营或采购里选数据感觉好的人转岗，3-6 个月带教成本低于外招磨合；二是降维招聘——不要求「跨境电商库存经理」的完整经验，招财务/数据分析背景+愿意学业务的人；三是工具过渡——先用补货公式+表格跑起来（L2A-07 方法），让工具承担 60% 的中枢职能，人只做例外判断。中枢岗的核心是「有人对断货和呆滞负责」，形式可以灵活。

**Q3: 五岗位的 KPI 会不会互相冲突，比如采购要降本、物流要时效？**  
A: 会，这正是设计供应链负责人岗位的原因。KPI 冲突的裁决原则：断货率和净利率是全局指标，岗位指标是局部指标——局部优化不能以全局恶化为代价。比如采购为降本换了便宜货代导致入仓延误，裁决结果必须是换回。实操建议：月度复盘会上把跨岗位 KPI 放一起看，冲突在桌面上解决，而不是让两个岗位私下互相拆台。
