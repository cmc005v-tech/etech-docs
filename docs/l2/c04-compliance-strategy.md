# L2C-04 全链路风控体系搭建

> **课时**：3 课时 | **路径**：L2-C 管理升级 | **主供素材包**：合规管理包

## 第 1 课时：合规组织架构与 SOP

### 一、三层合规体系架构

| 层级 | 角色 | 职责 |
|------|------|------|
| 治理层 | CCO/合规委员会 | 战略方向、资源审批、重大决策 |
| 管理层 | 合规部门 | 制度流程、培训监督、风险监测 |
| 执行层 | 业务对接人 | 日常执行、异常上报、SOP 落地 |

**组织规模适配原则：**
- "组织可以轻，责任不能空"
- 10 人以下：兼任合规责任人（三件事：知产监控+产品合规+平台规则）
- 1 亿以上：专职合规团队
- "没有 CEO 背书的体系推不动"——治理层必须有一把手参与

### 二、8 大核心 SOP

| SOP 编号 | SOP 名称 | 优先级 | 落地顺序 |
|----------|----------|--------|----------|
| SOP-1 | 新品上架合规审查 | P0 | 第 1 批 |
| SOP-2 | 订单履约合规 | P0 | 第 1 批 |
| SOP-3 | 知识产权监控 | P1 | 第 2 批 |
| SOP-4 | 产品合规认证管理 | P1 | 第 2 批 |
| SOP-5 | 数据隐私合规 | P1 | 第 2 批 |
| SOP-6 | 广告素材合规审查 | P2 | 第 3 批 |
| SOP-7 | 供应商合规管理 | P2 | 第 3 批 |
| SOP-8 | 应急响应与危机处理 | P2 | 第 3 批 |

**落地原则：** 新品上架→订单履约优先，其余按业务触点排序

## 第 2 课时：风险矩阵与 RegTech

### 三、合规风险矩阵二分法

| 风险类型 | 特征 | 应对策略 |
|----------|------|----------|
| 系统性风险 | 法规变化、不可控 | 监控+预案（提前准备） |
| 操作风险 | 执行不当、可控 | SOP+培训+自查 |

**风险矩阵评估维度：**
- 发生概率：高/中/低
- 影响程度：严重/中等/轻微
- 可控性：可控/部分可控/不可控

### 四、RegTech 与 AI 合规

**AI 合规能力：**
- AI 归类准确率 85-90%
- 2030 年 50% 合规审查 AI Agent 化

**分规模工具选型：**
| 体量 | 推荐工具 | 年投入 |
|------|----------|--------|
| <5000 万 | SaaS 合规工具 | 1-3 万 |
| 5000 万-2 亿 | 专业合规工具 | 5-15 万 |
| >2 亿 | 合规中台 | 20-50 万 |

### 五、合规成本 ROI

**合规是保险，不是费用：**
- 合规投入占营收 1-3%
- 不合规的代价：罚款（GDPR 最高 4% 全球营收）+ 下架 + 封号
- 合规的回报：准入资格+品牌信任+融资加分

## 第 3 课时：应急响应与风控体系

### 六、P0-P2 应急响应机制

#### 🧠 思维工具：先假设失败，再倒推原因——关键动作前跑一次 Premortem（极端情景模拟）

> 响应机制处理的是“已经发生的事”，Premortem 处理的是“还没发生但可能致命的事”——**在启动前假装它已经失败了，倒推失败原因**，绕过“我一定能成”的心理防御。大促、新品上架、新市场进入，每个关键动作前都应跑一次；让“低概率高杀伤”事件先在推演里死一次，防线才能提前布好。

| # | 假设的失败原因 | 概率(0-1) | 杀伤量级(高/中/低) | 触发条件 | 防线动作 | 责任人 |
|---|--------------|-----------|-------------------|---------|---------|--------|
| 1 | 账号/链接被暂停 | | | | | |
| 2 | 库存断货或爆仓 | | | | | |
| 3 | 物流延误/清关卡住 | | | | | |
| 4 | 被跟卖/价格战 | | | | | |
| 5 | 差评风暴（评分跌破 4.2） | | | | | |
| 6 | 其他（自填） | | | | | |

**使用规则：** ① 全员独立填写后再汇总，禁止讨论中互相“说服”（避免权威压制）；② 概率 ≥0.3 或杀伤量级“高”的死因必须有防线动作；③ 防线动作须在 48 小时内落地；④ 每次大促/新品/新市场前 1 周跑一次（20 分钟）。

::: tip 案例联动
风险清单式管理漏掉“低概率高杀伤”事件、大促前踩雷的案例，在[案例库](/cases/?model=极端情景模拟)筛选「极端情景模拟」即可一键深链查看，练习 Premortem 推演。
:::

| 级别 | 响应时间 | 场景 | 负责人 |
|------|----------|------|--------|
| P0 | 立即 | 账号被封/资金冻结/产品召回 | CEO 直接指挥 |
| P1 | 24 小时 | TRO/侵权诉讼/产品下架 | 合规负责人 |
| P2 | 72 小时 | 政策变动/供应商异常/物流中断 | 业务负责人 |

**产品召回时间线：** 2 小时（内部通报）→ 4 小时（评估影响）→ 8 小时（通知平台）→ 24 小时（启动召回）→ 72 小时（完成处置）

### 七、六大风险维度识别

| 维度 | 核心风险 | 预警指标 |
|------|----------|----------|
| 政策风险 | 关税变动/平台政策 | 政策更新频率 |
| 物流风险 | 港口拥堵/仓暴雷 | 物流时效偏差 |
| 库存风险 | 断货/呆滞 | 库存周转天数 |
| 上游风险 | 供应商暴雷/品质 | 来料合格率 |
| 汇率风险 | 汇率波动 | 月度汇差 |
| 竞争风险 | 价格战/新品替代 | 市场份额变化 |

#### 🧠 思维工具：复杂系统里，事故不是谁错了——给事故链做压力测试（正常事故）

> 旺季断货、多仓错配、政策+物流联动暴雷——复盘时每个部门都“没犯错”，但链条组合就是事故。当系统**交互复杂且紧密耦合**时，事故是“正常的”：无法靠“更小心”消除，只能靠“改结构”降低——把目标从“零事故”改为“事故可恢复”，把复盘从“人肉追责”改为“结构复盘”。

| # | 检查环节 | 复杂度×耦合度(0-100) | 潜在事故链 | 恢复时间目标（RTO） | 结构改进动作 |
|---|---------|--------------------|-----------|------------------|-------------|
| 1 | 旺季履约链 | | 延期→断货→排名掉 | ≤7 天 | 违约金条款/安全库存 |
| 2 | 多仓协同 | | 库存错配→跨仓发 | ≤48 小时 | 分仓规则简化 |
| 3 | 供应商切换 | | 打样延迟→错过船期 | ≤14 天 | 并行打样/锁定期 |
| 4 | 政策+物流联动 | | 集中出货→拥堵→错配 | ≤21 天 | 分散出货窗口 |

**使用规则：** ① 复杂度 × 耦合度 ≥50 的环节，默认“事故必然发生”，必须写 RTO 与结构改进；② RTO 超出现有能力的环节，旺季前强制做全链条模拟走查；③ 事故复盘只问一句：“什么结构让这个错误必然发生”，而不是“谁害的”。

:::

## 本课小结

| 核心要点 | 关键结论 |
|----------|----------|
| 组织架构 | 三层体系+分规模适配+一把手背书 |
| SOP 体系 | 8 大 SOP 分三批落地，P0 两个模板已展开可直接套用（第3课） |
| 风险矩阵 | 系统性 vs 操作风险二分法，保险与外部顾问占合规投入大头（第4课） |
| 应急响应 | P0-P2 三级+产品召回时间线，单人/小团队有裁剪版（第5课） |
| 小卖家专项 | 外包风控三条：担责规则/协议条款/交付验收（第5课） |

::: tip 学生模拟分支（无企业背景的学员）
用虚拟公司代入本课实训：设定一家年营收 100-500 万、单平台起步的虚拟公司（可沿用 L2B-01 商业计划中的设定），用假设数据完成全部任务并标注推导过程。单人/小团队裁剪版（第5课）适合学生直接套用。
:::
