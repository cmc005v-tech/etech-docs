## 一、为什么需要跨模块整合

### 1.1 单模块视角的局限

业务问题几乎从不发生在单一模块内。销量下降可能是广告问题、库存问题或竞品问题，只看广告报表永远找不到真正原因。

**典型误判案例：** 某卖家销量下滑，广告团队加预算应对，结果 ACOS 恶化但销量继续跌——真正原因是海外仓爆仓导致配送时效从 2 天变 7 天，转化率崩了。单模块视角让团队在错误的方向上烧钱。

### 1.2 跨模块指标地图

| 业务问题 | 涉及维度 | 关键指标 | 根因候选 |
|----------|----------|----------|----------|
| 销量下降 | 销售+广告+库存 | BSR、曝光量、库存 | 广告预算不足？断货？竞品降价？ |
| ACOS 飙升 | 广告+销售 | ACOS、CVR、CPC | 转化率下降？CPC 上涨？关键词失效？ |
| 利润下滑 | 销售+广告+库存 | 净利率、TACOS、仓储费 | 广告费过高？仓储费增加？退货率上升？ |
| 退货激增 | 销售+合规+供应链 | 退货率、差评、配送时效 | 描述不符？物流损坏？质量波动？ |

## 二、跨模块诊断四步法

### 步骤1: 定义问题与时间窗

- 用一句话写清问题：什么指标、什么幅度、什么时间开始
- 示例：ACOS 从 25% 升到 45%，始于 8 月 5 日

### 步骤2: 拉齐多模块数据

- 以问题发生日为锚点，拉取前后各 2 周的五维数据
- 重点看哪些指标与问题同步变化（同步变化 = 相关线索）

### 步骤3: 建立因果假设

- 每个相关线索写成一个假设：因为 X 变化，导致 Y 恶化
- 按可能性排序，逐个验证

### 步骤4: 验证与行动

- 验证方法：数据交叉验证、小范围实验、历史对照
- 确认根因后制定行动项：负责人、完成时间、验证指标

## 三、三大高频问题的诊断模板

### 3.1 销量下降诊断模板

| 检查项 | 数据来源 | 判断标准 |
|--------|----------|----------|
| 曝光是否下降 | 广告报表+搜索报告 | 曝光降幅>20% 优先查流量端 |
| 库存是否正常 | FBA 库存 | 断货或配送时效恶化 |
| 竞品动作 | 竞品监控 | 降价、上新、大促 |
| 外部因素 | 品类大盘 | 季节性、政策变化 |

### 3.2 ACOS 飙升诊断模板

| 检查项 | 判断逻辑 |
|--------|----------|
| CPC 是否上涨 | CPC 涨→市场竞争加剧，检查出价策略 |
| CVR 是否下降 | CVR 降→问题在 Listing 或流量质量 |
| 新增词是否失控 | 新词高花费零转化→立即否定 |
| 大促后回落 | 正常现象，观察一周再判断 |

### 3.3 利润下滑诊断模板

| 检查项 | 判断逻辑 |
|--------|----------|
| 广告费占比 | TACOS 上升→广告效率问题 |
| 仓储费变化 | 长期仓储费→呆滞库存处理 |
| 退货率 | 退货率上升→质量或描述问题 |
| 汇率与采购成本 | 外部环境变化→价格策略调整 |

## 四、实战案例：利润下滑的跨模块追查

**背景：** 深圳某宠物用品卖家，季度利润环比下滑 40%，但销售额只降了 8%，团队找不到原因。

**跨模块追查过程：**

| 轮次 | 假设 | 验证结果 |
|------|------|----------|
| 1 | 广告费失控 | 排除：TACOS 持平 |
| 2 | 采购成本上涨 | 部分成立：成本+6%，但解释不了全部 |
| 3 | 退货率上升 | 成立：退货率从 5% 升到 11% |
| 4 | 退货为何上升 | 差评归类发现 70% 新差评指向新换的供应商批次质量 |

**根因链：** 供应商变更→质量波动→退货率上升→利润下滑，而销售额端因广告托底只小幅下滑，掩盖了问题。

**解决动作：** 换回原供应商+库存全检，6 周后退货率回落 6%，利润恢复。

::: warning 核心要点
跨模块诊断的核心纪律：先排除再聚焦。每个假设都要有数据验证，没验证的假设只是猜测。利润问题的根因往往藏在最不起眼的模块里。
:::

## Q&A 预案

**Q1: 跨模块数据分散在不同后台，怎么高效拉齐？**  
A: 三个层次：最简版是固定每周一人工导出五个后台的报表到统一模板（小团队够用）；进阶版用 ERP 或数据工具自动拉取汇总；高级版是 API 对接建仓库。关键不在工具而在节奏：先把拉数据变成每周一的固定动作，自动化可以逐步升级。

**Q2: 多个指标同时恶化，先查哪个？**  
A: 按因果链上游优先：先看流量端（曝光、CPC）再看转化端（CVR）最后看后端（退货、仓储）。因为上游变化会传导到下游，修上游一次解决多个下游问题。如果时间线清晰，从最早恶化的指标查起，那通常就是源头。

**Q3: 诊断出根因但跨部门，谁负责推进？**  
A: 每个根因分析必须产出唯一负责人的行动项，这是复盘机制的核心纪律（详见第6课）。常见模式：运营发起诊断，但根因在供应链，则由供应链负责人领行动项，运营跟踪验证指标。没有唯一负责人的行动项，三周后一定不了了之。
